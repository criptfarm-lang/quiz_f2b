# quiz_f2b — обучение и тесты менеджеров F2B

Статика на GitHub Pages: `https://criptfarm-lang.github.io/quiz_f2b/`.
Билд поднимается автоматически через 60–90 сек после `git push origin main`,
проверка: `gh api repos/criptfarm-lang/quiz_f2b/pages/builds/latest`.

## Файлы

| Файл | Что |
|---|---|
| `course_f2b.html` | Основной курс — 7 модулей с уроками + объединённый тест менеджера |
| `attestation_f2b.html` | Финальный экзамен, таймер |
| `img/` | Картинки уроков (WebP), подгружаются лениво |
| `balasanyan.html`, `sklyar.html`, `merzlyakova.html` | Индивидуальные тесты |
| `scripts/extract_images.py` | Вынос base64-картинок из курса в `img/` |

## ВАЖНО: картинки уроков — только файлами, не base64

Курс открывается менеджерами с рабочих компьютеров и телефонов. Всё содержимое
курса лежит в одном HTML, поэтому браузер обязан скачать файл целиком до первой
отрисовки — пока файл едет, у менеджера пустой белый экран.

17.08.2026 курс дорос до 8,1 МБ (96,5% веса — 64 картинки в base64) и перестал
открываться: жалоба «обучение висит». Картинки вынесены в `img/`, HTML сжался до
276 КБ, картинки грузятся лениво и только для открытого урока.

Правило: **новую картинку в урок класть файлом в `img/` и ссылаться относительным
путём**, с `loading="lazy" decoding="async"`:

```html
<img src="img/l065.webp" loading="lazy" decoding="async" alt="...">
```

Если картинка всё-таки заехала в base64 (например, вставлена из docx собственника)
— прогнать `python3 scripts/extract_images.py`, он вынесет всё разом.
Ориентир: `course_f2b.html` должен оставаться в пределах ~500 КБ.

## Проверка перед коммитом

```bash
# синтаксис JS в курсе
node -e "const m=require('fs').readFileSync('course_f2b.html','utf-8').match(/<script>([\s\S]*?)<\/script>/); new Function(m[1]); console.log('OK')"
# не завелось ли base64 обратно
grep -c 'data:image/' course_f2b.html   # должно быть 0
```

При grep-поиске по курсу картинки больше не мешают — файл текстовый.
